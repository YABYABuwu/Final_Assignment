# กริดกำแพงสี่ด้าน

กริดเดินใช้ `exploration.step_m` เป็นขนาดช่อง (ปัจจุบัน 0.60 เมตร) ศูนย์กลางช่อง `(0,0)` อยู่ที่ pose เริ่ม DFS และแกนกริดหมุนตาม yaw เริ่มต้น แต่ละช่องมีด้าน `x+`, `y-`, `x-`, `y+` และขอบระหว่างช่องใช้ข้อมูลเดียวกัน เช่น `x+` ของ `(0,0)` ตรงกับ `x-` ของ `(1,0)`

## การสร้างกำแพง

`CellWallGrid` อยู่ใน `src/slam.py` เพราะ occupancy ละเอียดเดิมเก็บเพียงจุดปลายรังสีและไม่มีข้อมูลว่าด้านใดของช่อง DFS มีกำแพง คลาสนี้รับ scan ที่ DFS ยืนยันแล้วจาก `SensorLogger`/`SlamWorker` เดิม ไม่มี subscription เพิ่ม

เมื่อ gimbal หันถึงเป้าหมาย, SDK action สำเร็จ และได้ ToF ใหม่ตรงทิศ ขอบช่องปัจจุบันใช้ `exploration.wall_threshold_mm`: ToF ไม่เกิน 500 มม. เป็น `wall`; มากกว่า 500 มม. เป็น `open` โดยไม่มีระยะเผื่อขนาดตัวหุ่น ค่า 0/ไม่ใช่ตัวเลขถูกข้ามและรอค่าที่ใช้ได้ โดยไม่อัปเดตแผนที่หรืออนุญาตให้เดินจาก scan เก่า; หาก callback ยังส่งค่า 0 ซ้ำ ระบบรอค่าที่ใช้ได้โดยไม่ยกระดับเป็น error; หาก callback ขาดหรือ timestamp ไม่สด ระบบหยุด ข้อมูลเก่าหรือ scan ที่ยังไม่ครบไม่ใช้ตัดสินใจ

หลังสแกนครบสี่ทิศในช่องใหม่ DFS ใช้ผนังที่วัดตรงจัดตำแหน่ง ถ้ามีผนังสองฝั่งในแกนเดียวกันจะวัดทั้งคู่และขยับให้ระยะเท่ากัน ถ้ามีฝั่งเดียวจะใช้ระยะเป้าหมาย 25 ซม. (`exploration.alignment.wall_distance_m`) จากกึ่งกลาง chassis รวม offset หัว ToF การขยับแต่ละแกนใช้ PID ของ `ChassisController.move_to` และจำกัดแต่ละช่วงด้วย `max_shift_m`; ไม่ขยับเมื่อคลาดไม่เกิน `tolerance_m` หลังขยับสแกนผนังที่ใช้ใหม่เพื่อตรวจผล

เกณฑ์หยุดฉุกเฉิน `exploration.emergency_stop_distance_m` (20 ซม.) ใช้เฉพาะการเดินตามกริดทั้งขาไปและขากลับ ไม่ใช้ใน alignment ก่อนเดินหัน ToF ไปทางที่จะเคลื่อนหนึ่งทิศและรอ telemetry/action/scan ใหม่ ระหว่างเดิน `ChassisController.move_to` ตรวจข้อมูลสดจาก `SensorLogger` ด้วย `stop_if`; หากระยะกึ่งกลาง chassis ถึงกำแพงไม่เกินเกณฑ์จะหยุดล้อทันที ถ้าผ่านครึ่งทางของช่วงเดินให้ใช้ pose ที่หยุดจริงเป็นจุดกลางช่องปลายทาง ถ้ายังไม่ถึงให้คงช่องต้นทางและปรับขอบทางนั้นเป็นกำแพง บันทึก `exploration.last_motion_stop` เพื่อแสดงผลสดและย้อนหลัง

หากตั้ง `exploration.alignment.enabled: false` ระบบจะข้ามการจัดตำแหน่งและการสแกนยืนยันหลังขยับ แต่ยังสแกนกำแพงสี่ทิศของช่องใหม่และใช้เกณฑ์ ToF สำหรับ DFS ตามเดิม

DFS ใช้ `exploration.tof_median_window` (ค่าเริ่มต้น 3; จำนวนคี่ 1–9) รอ scan ใหม่คนละ timestamp ที่ gimbal หันตรงทิศ หลัง SDK action สำเร็จ แล้วใช้ค่ามัธยฐานเทียบ `wall_threshold_mm` ทั้งการสแกนสี่ทิศและการตรวจซ้ำก่อนเดิน หาก scan ไม่ครบจะยังไม่ตัดสินใจ ค่าที่ไม่ใช่ระยะจริง (`0`, `65535`) ไม่ใช้ทำแผนที่หรือเก็บในหน้าต่างวัด ข้อมูล ToF ดิบใน CSV ไม่ถูกกรอง

ขอบไกลตามแนวรังสียังคำนวณจากจุดชนที่ชดเชย pose และ offset ของ ToF เพื่อวาดกริดและแชร์ขอบระหว่างช่อง แต่ผลอนุมานจากช่องไกลเขียนทับขอบที่เคยวัดตรงจากช่องติดกันไม่ได้ แม้ผลอนุมานนั้นใหม่กว่า ขอบไกลที่อนุมานว่าเปิดใช้สั่งเดินไม่ได้จนกว่าจะสแกนจากช่องปัจจุบันเอง ผลวัดตรงจากสองฝั่งของขอบเดียวกันใช้ค่าที่วัดล่าสุด ดังนั้นเกณฑ์ 500 มม. ใช้เฉพาะการตรวจขอบติดตัวรถ ส่วน occupancy ละเอียดยังฉายระยะจริงตามเดิม

## การเดินและการถอยกลับ

DFS สแกนครบสี่ทิศเมื่อเข้าช่องใหม่ และสแกนทิศที่จะไปช่องใหม่ซ้ำทันที ข้ามขอบได้เมื่อสถานะขอบเป็น `open` และ ToF ใหม่จากช่องปัจจุบันมากกว่าเกณฑ์ เมื่อเดินกลับเข้าช่องที่เคยไปแล้วจะไม่สแกนสี่ด้านใหม่ แต่หัน ToF ไปทางเดินกลับหนึ่งทิศเพื่อเฝ้าระยะฉุกเฉิน และตรวจว่าขอบร่วมในกริดยังเป็น `open` ก่อนเคลื่อนที่ การตรวจ pose/status สดและการหยุดเมื่อ SLAM worker ผิดพลาดยังคงเดิม

ก่อนสั่งเดินแต่ละช่วง รวมทางกลับและการขยับ alignment ระบบจับ yaw chassis สดตาม `exploration.heading_source` แล้วส่ง yaw นั้นเป็นเป้าหมายคงที่ให้ PID ระหว่างช่วงเดิน บันทึกค่าเป้าหมายล่าสุดใน `exploration.last_motion_heading` ของแผนที่และ run summary; CSV attitude/gimbal ยังเก็บค่าที่วัดจริงตลอดทาง

## Dashboard, export และ review

- มุมมองปกติแสดงขอบกำแพงสีส้ม ทางเปิดสีเขียว ขอบอนุมานเป็นเส้นประ และขอบยังไม่รู้เป็นเส้นประเทา พร้อมพิกัดช่องและสถานะสี่ด้าน แกนจอ +X ขึ้น / +Y ขวา ส่วนแกนช่องอ้างอิง `base_pose`
- ส่งออกภาพกริด DFS เป็น PNG ผ่านปุ่ม “ส่งออก Grid PNG” หรือ `/api/map/export?format=grid-png`; บันทึก `latest-grid.png` และ `map-grid.png` ในโฟลเดอร์รันโดยอัตโนมัติ ภาพนี้จัดแกนตามกริด (+X ขึ้น, +Y ขวา) และเก็บสีของกำแพง/ทางเปิด/ยังไม่รู้ แยกจากภาพ occupancy ละเอียด
- ช่องเลือก “แสดง occupancy ละเอียด” เปิดกริดเดิมร่วมกับกำแพง จึงตรวจเทียบข้อมูลได้
- `robomaster-occupancy-grid` ยังคง version 1 และลำดับ `data` เดิม เพิ่ม `exploration.cell_grid` version 1 ประกอบด้วย `cell_size_m`, `base_pose`, `current`, `cells[].index`, `cells[].sides` ซึ่งแต่ละด้านมี `state` และเมื่อวัดที่ช่องนั้นแล้วจะมี `source` (`direct`/`inferred`), `checked_from_here`, `observed_at` และเมื่อวัดตรงจะมี `range_mm`, `wall_threshold_mm`, `measured_from` (run เก่ายังอาจมี `required_range_mm`/`clearance_ok`)
- Map JSON/ROS ZIP (`slam.json`) เก็บกริดกำแพงด้วย ส่วน ROS PGM คงเป็น occupancy ละเอียด การ import ตรวจ schema และขอบร่วมที่ขัดแย้งกันก่อนแก้ map; ไฟล์เดิมที่ไม่มี `cell_grid` ยังเปิดได้
- การเปิด map เก่าแสดงกริดที่บันทึกไว้ การเริ่ม DFS รอบใหม่สร้างกริดช่องจาก pose เริ่มใหม่และสแกนใหม่ ไม่ใช้ผลตรวจเก่าอนุญาตให้เดิน
- `run_summary.json.exploration` เก็บ snapshot สุดท้ายรวม `scanned_cells` แม้รันล้มเหลว หน้า review แสดงตารางกำแพงแยกจากตัวเลื่อนเวลา ยังไม่มีประวัติกริดทุกช่วงเวลา รันเก่าแสดงว่าไม่มีข้อมูลกริด
